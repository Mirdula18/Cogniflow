# Mock scenarios (P3 demo data)

All datasets are **synthetic**, generated by the team for demonstration. No company, client or personal data. Store under `web/lib/mock/datasets/` (CSV + profile JSON) and `web/lib/mock/scenarios/` (event lists matching `API_CONTRACT.md`). Mirror the same files in `api/scenarios/` for the live stub.

## Datasets

| ID | File | Rows × cols | Deliberate mess |
| --- | --- | --- | --- |
| `ds_delivery` | project_delivery.csv | 480 × 9 | Mixed date formats (DD/MM/YYYY + YYYY-MM-DD), 14 duplicate tasks, blank owners |
| `ds_sales` | regional_sales.xlsx | 1,200 × 8 | Revenue stored as text with "₹" and commas, region spelt 3 ways ("TN", "Tamil Nadu", "tamilnadu") |
| `ds_tickets` | support_tickets.csv | 900 × 7 | Free-text priority ("High", "high ", "P1"), 6% null resolution time |
| `ds_costs` | project_costs.csv | 300 × 6 | Merged header row in export, negative cost typos |
| `ds_hr` | team_allocation.csv | 150 × 6 | Percent allocations > 100% for some people, duplicated names with different IDs |

Generate them with a seeded script `web/lib/mock/generate.ts` (seed 42) so they are reproducible; commit the script and the outputs.

## Scenarios

| ID | Dataset | Question | Steps | Path shown |
| --- | --- | --- | --- | --- |
| `sc_01` | ds_delivery | Why did delivery slip last month? | profile → clean dates & dedupe → delay by team → top causes → chart | Happy path |
| `sc_02` | ds_sales | Which region's revenue fell most this quarter? | profile → parse ₹ text → normalise region → QoQ change → bar chart | **Error → retry → success** (attempt 1 fails to parse "₹1,20,000") |
| `sc_03` | ds_tickets | Are P1 tickets resolved within 24 hours? | profile → normalise priority → handle nulls → % within SLA → metric + table | Happy path, metric artifact |
| `sc_04` | ds_costs | What is the cost overrun per project? | profile → fix header → flag negatives → overrun % → table | Happy path, table artifact |
| `sc_05` | ds_hr | Who is over-allocated next sprint? | profile → dedupe people → sum allocation → … | **3 failed attempts → not_verified** (ambiguous duplicate IDs); fallback message |

## Scenario file shape

```json
{
  "scenario_id": "sc_02",
  "dataset_id": "ds_sales",
  "question": "Which region's revenue fell most this quarter?",
  "events": [
    { "seq": 1, "type": "run_started", "delay_ms": 0, "question": "..." },
    { "seq": 2, "type": "plan", "delay_ms": 600, "steps": [{ "id": "s1", "goal": "Parse revenue text to numbers" }] },
    { "seq": 3, "type": "code", "delay_ms": 800, "step_id": "s1", "attempt": 1, "language": "python", "source": "df['revenue'] = df['revenue'].astype(float)" },
    { "seq": 4, "type": "error", "delay_ms": 500, "step_id": "s1", "attempt": 1, "error_type": "ValueError", "message": "could not convert string to float: '₹1,20,000'" },
    { "seq": 5, "type": "retry", "delay_ms": 300, "step_id": "s1", "next_attempt": 2, "reason": "Strip currency symbol and Indian digit grouping" }
  ]
}
```

`run_id`, `ts` and `contract_version` are filled in by the player at replay time.

## Rules for writing scenarios

- Code shown must be **real, runnable pandas** that would produce the shown output on the generated dataset. Verify by running it once in a notebook; save that notebook under `docs/scenario-checks/`.
- Summary numbers must match the artifacts exactly.
- Total replay time per scenario: 8–20 seconds.
- Each scenario includes at least one `stdout` line per step.
